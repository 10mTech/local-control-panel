lcp · terminal panel for macOS · Go · pre-release

Every project on one screen.

lcp is a keyboard-driven terminal panel for the folder where your projects live. It shows each project's stack, git state, running servers, disk use and age. One keystroke opens a project, starts its dev server, pulls it, cleans its build folders or archives it. Every action goes into a hash-chained audit log you can read inside the panel.

1 Screens

Read a project's state from one row.

lcp finds every git repo up to three levels under your projects folder, groups folders that only hold repos, and keeps watching for new clones. Git and ports refresh every ten seconds while it's open. Sizes are measured in the background and cached.

3 Safety

It moves things to the Trash. It never deletes them.

lcp sits next to work you care about, so the rules below are fixed in code rather than left to settings. It changes nothing in your projects beyond the actions listed here.

Clean · metrics-console 
Move these folders to the Trash:
  node_modules            20M

Left alone:
  target               symlink, never followed
  dist                 holds files tracked in git

Total 20M. Reinstall or rebuild to get them back.
The space is freed when you empty the Trash.
y move to Trash · n cancel

What x shows on metrics-console in the demo. Nothing moves until you press y, and saying no is logged too.

  • Stops only what it started

    A dev server is stopped by its recorded PID, after checking the process still has the same start time. lcp never kills by name or pattern.

  • Cleans from an allowlist

    Only node_modules, target, .next, dist, build, .turbo and src-tauri/target, directly in the project, and never while it's running.

  • Shows the plan, then asks

    Clean, archive, restore, init and fetch all preview what will happen and wait for y. Trashing a whole project needs its path typed out.

  • Moves, never deletes

    Clean and trash use the macOS Trash, and archive is a rename. Finder's Put Back undoes them until you empty the Trash.

  • Git that can't lose work

    Fetch, pull --ff-only, init, status and log. Never push, reset, checkout, stash or force. A repo that wants a password fails instead of prompting.

  • No shell strings

    Commands run as argument lists, so paths with spaces are safe. The one shell, the dev-server wrapper, is built with strict quoting.

  • Stays inside your folder

    Every path an action touches must resolve, after symlinks, inside the projects folder or the archive.

  • One action at a time

    While an action runs, the next one is refused with wait. Git status runs without taking the index lock, so your editor never fights it.

4 Audit

Every action leaves a trail you can check.

The log is plain JSON Lines in ~/.local/state/local-control-panel/audit/, one file per month, append-only and synced after every line. It is never pruned, and the panel never rewrites it.

  • Two lines per action

    An intent line before it runs and a result line after, sharing one ULID. If the panel crashes halfway, the intent is still there.

  • The exact command

    Each entry records the project, its remote, the argv, the key that triggered it, the outcome, exit code and duration. A clean lists every path it moved and its size.

  • A hash chain

    Each line's prev is the SHA-256 of the line before it. Edit or remove a line and the Audit screen shows exactly where the chain breaks.

  • Secrets masked

    GitHub and API tokens, bearer headers, password=-style values and credentials in URLs become ****. Environment variable values are never logged.

auditchain ok · 5 lines 2026-11.jsonl · sample

A sample log with made-up projects. The check is the same rule the Audit screen uses: hash each line's exact bytes with SHA-256 and compare the result with the next line's prev. It runs in your browser.

5 Install

Build it, point it at your folder, press a key.

lcp is a single Go binary. It needs no server, opens no network port and keeps its own files outside your projects.

  1. Check the requirements

    • macOS 15 or later. Cleanup uses the system's /usr/bin/trash.
    • Go 1.24 or later.
    • herdr 0.8.0 or later for the actions that open panes and run servers. Without it the dashboard still works, the top bar says herdr off, and actions tell you why they can't run.

  2. Install

    $ go install github.com/10mTech/local-control-panel/cmd/lcp@latest

    Run it again to update. It installs lcp into $(go env GOPATH)/bin; make sure that is on your PATH, or set GOBIN to install somewhere that already is.

  3. Point it at your projects

    The first run writes ~/.config/local-control-panel/config.toml with defaults. Every key is optional; set root to your projects folder and github_users to your accounts.

    root = "~/Projects"
scan_depth = 3                       # how deep to look for git repos
archive = "~/Projects/archive"
editor = "nvim"
refresh_seconds = 10                 # git and port refresh while open
github_users = ["your-github-name"]  # other owners show as "not mine"

[activity]                           # days since the last change
active = 14
warm = 90
dormant = 365                        # older is abandoned

# Per-project overrides, keyed by path under root
[projects."news-reader"]
dev = ["pnpm", "tauri", "dev"]
port = 1420

  4. Run it in a herdr pane

    Type lcp. A few flags help outside the terminal UI:

    -list
    Print the scan as plain text and exit.
    -snapshot dashboard -size 160x45
    Render one screen to stdout. Also takes help, audit, runs and detail:<path>. The images on this page came from it.
    -config PATH
    Use another config file, with its own audit log and runs when it sets state_dir.
    -version
    Print the version.

  5. Uninstall

    Stop the dev servers the panel started (s on the Runs screen), quit, and move the binary to the Trash. Removing the config and state folders is optional; keep the state folder if you want the audit history.

    $ trash "$(go env GOPATH)/bin/lcp"
$ trash ~/.config/local-control-panel ~/.local/state/local-control-panel

    If you set XDG_CONFIG_HOME, XDG_STATE_HOME or state_dir, remove those folders instead. Nothing lives inside your projects, and anything lcp cleaned, trashed or archived stays where it is.

Troubleshooting

lcp: command not found
Go's bin folder isn't on your PATH. Add export PATH="$HOME/go/bin:$PATH" to ~/.zshrc and open a new terminal.
herdr off
lcp can't reach herdr. Install herdr 0.8.0 or later and start lcp from a herdr pane. The dashboard works without it.
fetch or pull fails
lcp never prompts for a password. Set up an SSH key or a credential helper, then try again. The error is in the Audit screen (a).
unknown keys ignored
A key in config.toml is misspelled or not supported. The warning names it.
anything else
Check debug.log in ~/.local/state/local-control-panel, then open an issue.

Small on purpose.

Local only

No server, no network listener, no telemetry. The only network traffic is the git fetch and pull you ask for.

Not a window manager

herdr owns workspaces and panes. lcp asks it to act and reads its JSON replies.

Mac, single user

It relies on macOS's Trash, lsof and Finder, and it watches one projects folder.

Its files stay apart

Audit log, run logs and caches live in ~/.local/state/local-control-panel, so scans and cleanups never touch them.
